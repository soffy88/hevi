## The chain

```
Intent
  -> ProviderCatalogue      declared identity + facts
  -> ProviderPolicy        facts + requirements = eligibility
  -> ProviderDecision      what may be used, and under what terms
  -> ProviderRuntimeStatus is it answering right now
  -> AcquiredSource        bytes, digest, and the event that fetched them
  -> ExecutionRun          one attempt
  -> ProductionReceipt     artifact produced and validated
  -> ArtifactValidation    requirements observed and met
  -> QualifiedArtifact
```

Each layer refuses for its own reason, and no layer's vocabulary is shared with
another's on the wire.

## 15 invariants, all holding

Every one is asserted in a test, and every one was mutation-verified at least once.

| invariant | the defect it prevents |
|---|---|
| no second asset authority | a parallel asset registry |
| no second provider fact source | a probe or runtime model restating what a provider is |
| no second probe client | a second HTTP client beside the existing probe |
| no second production authority | a second `ExecutionReceipt` |
| one check type | `ValidationCheck` and `ArtifactCheck` drifting apart |
| runtime / acquisition / execution / artifact states disjoint from `RunState` | `"failed"` meaning two things after serialisation |
| `uri != evidence` | a well-formed link treated as an acquired asset |
| `artifact_exists != production_success` | a receipt issued from a path |
| `passed` derived, never declared | a caller asserting a verdict with nothing observed |
| validation never repairs | a validator modifying what it inspects |
| unobserved requirement cannot pass | a missing probe becoming a silent pass |

## Two duplications resolved rather than reproduced

**`ExecutionReceipt`.** P6 already defined one meaning *a delegate ran*. P8.3 needed
proof that *an artifact was produced and validated* — different subject, different claim.
Defining the second would have put two meanings behind one name and breached
`NO_SECOND_PRODUCTION_AUTHORITY`. Hence `ProductionReceipt`, asserted independent of
P6's.

**`ValidationCheck` / `ArtifactCheck`.** P8.3's took `passed` as a *field*, so a caller
could declare a verdict with nothing observed. P8.4 extended the one type rather than
adding a second: `passed` is now derived, and `ArtifactCheck` is an alias.

Both are the same failure mode, and both were caught by asking a single question:
*is there already something here with this name?*

## Two package hazards

**`hevi/execution/` was not empty.** It is P0-E — execution plans, DAG repair,
`Scheduler`, `ResourceSnapshot`. P8.3's first `__init__.py` overwrote it and broke
`hevi.tasks.repository` on import. Now additive: all 11 P0-E exports preserved, 8 P8.3
appended, 475 P0-E tests green.

This produced a standing rule: **scan for existing authorities before assuming a
directory is empty.** Every spec from here should begin with that scan.

Four architecture tests in this repo passed while enforcing nothing. The pattern is in
`docs/TESTING-PRINCIPLES.md`:

token `write`. P9 inherits the rule.
