# 商鞅演绎 4 条回测报告（2026-10-24）

问题：如果这套门禁在 2026-10-24 生成前跑过，会拦住什么、拦不住什么。

## 回测设定（假设写明，不藏）

- 对白来源：`output/shangyang_lu_v2/preproduction.json` 的 storyboard 原文。
  假设 Flow prompt 对白＝原稿对白；支撑：v2 转写里出现原稿原句
  （如“死守”），说明未大删。**实际 Flow prompt 文本未存档**，若当时
  prompt 删减过对白，字／秒数会下移——但转写证据支持未大删。
- 字数口径：门禁只计 CJK 表意字与数字字母，标点不计；原稿 `chars`
  字段含标点（75／70／71），门禁计数为 65／60／60——两种口径下
  结论一致（都超硬上限）。
- 首帧：以各场景分镜静帧作代理；debate_B 首帧实际未知，用 beat02 代理。
- 台账：生成前余额按月度 1000／当日 50（实花前状态）。
- 模型：Veo Fast，8 秒窗，20 credits／条。

## 拦不住的三项（明说）

1. **beat08 脸漂移——自动判定未达成。** 13 拍与卫鞅定妆的直方图距离
   全在 0.618–0.652 之间，beat08（0.6291）排第 4 近——离“最像”比
   离“最不像”还近。直方图是场景色彩信号，不是人脸信号，无法区分
   脸漂移。门禁现状：只出人工目视清单＋比对图
   （`preflight_backtest/beat08_vs_weiyang.png`），脸项须人眼判。
   不许对外称“已自动验真脸一致”。
2. **debate_B 牌匾伪文字——自动判定未达成。** 本机无 OCR（tesseract
   未装），伪文字无法自动检出。门禁现状：场景含文字载体时出 WARN
   ＋人工目视项；debate_B 的 BIAN 朝堂场景未含牌匾词，实际连 WARN
   都没触发——伪文字全靠人眼看首帧。这是真缺口，待 OCR 或 VLM
   验真手段接入后再升级为自动项。
3. **个别字转写含糊——生成前无法判定。** 这是生成后问题：门禁只能拦
   超窗赶话（诱因），含糊本身由生成后 ASR 验真捕获，再记进通过率
   台账（本回测记为 dialogue_garbled 2 次）。

  的 false positive（"OK" 子串命中编译器 "spoken"），已修为拉丁词
  词边界匹配＋回归测试。
- 无文字声明：编译器输出默认带 no-text 段，4 条均通过。
- 定妆引用：4 条均附定妆图，无 WARN。
- 画幅：静帧 1376×768（比值 1.792）与 16:9（1.778）差 0.014，在
  0.05 容差内，通过。

  批量级应出 WARN（动用月度池），当前 `run_gate` 只做单条预算，
  批量预算门是已知待补项（不影响单条结论）。
