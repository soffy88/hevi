# Hevi 项目踩坑记录与解决方案

> **目的**：记录常见问题和解决方案，加速新开发者上手

## 环境配置类问题

### 1. Python 版本不兼容
**问题**：某些依赖在特定 Python 版本下无法安装或运行
**解决方案**：使用 Python 3.10+，推荐使用 pyenv 管理版本
**验证命令**：`python --version`

### 2. 依赖冲突
**问题**：多个依赖包之间版本冲突
**解决方案**：使用 `pip install --no-deps` 单独安装冲突包，或使用虚拟环境隔离
**预防措施**：定期更新 `requirements.txt`，使用 `poetry` 或 `pipenv` 管理依赖

### 3. GPU 资源不足
**问题**：TTS 或渲染任务因 GPU 内存不足而失败
**解决方案**：实现资源调度器，按需分配 GPU，设置内存限制
**相关代码**：`hevi/gpu/providers.py`

## 生产环境问题

### 4. 静默降级导致质量问题
**问题**：当首选服务不可用时，系统自动切换到次优方案而不通知
**解决方案**：实现硬门机制，任何服务切换都需要显式确认
**相关实现**：`configs/tts_routing.json` 和 `scripts/validate_tts_provider.py`

### 5. 字幕同步不准
**问题**：生成的字幕与音频时间轴不同步
**解决方案**：强制使用真实 ASR 结果，禁止基于字符数的估算
**相关技能**：`skills/caption-from-audio`

### 6. 数字人生成未经确认
**问题**：数字人视频在没有试听确认的情况下生成
**解决方案**：实现数字孪生保护机制，必须经过审批才能使用特定声音
**相关技能**：`skills/digital-twin-guard`

## 架构设计问题

### 7. 异常处理不当
**问题**：错误被静默捕获，导致问题难以追踪
**解决方案**：采用防御性编程，所有错误都要明确处理或向上抛出
**最佳实践**：使用 `try-except-raise` 模式，保留原始错误信息

### 8. 配置管理混乱
**问题**：配置分散在多个地方，难以维护
**解决方案**：集中管理配置，使用 Pydantic 设置类验证
**相关文件**：`hevi/core/config.py`

### 9. 并发访问冲突
**问题**：多个进程同时访问共享资源导致竞争条件
**解决方案**：使用锁机制和资源池管理
**相关实现**：`hevi/gpu/providers.py` 中的调度器

## 性能优化问题

### 10. 内存泄漏
**问题**：长时间运行后内存占用持续增长
**解决方案**：及时释放不需要的对象，使用生成器处理大数据
**监控命令**：`python -m memory_profiler your_script.py`

### 11. 瓶颈识别困难
**问题**：难以定位性能瓶颈所在
**解决方案**：集成性能监控，使用 `cProfile` 进行分析
**相关工具**：`hevi/observability/instrumentation.py`

## 测试相关问题

### 12. 测试覆盖率不足
**问题**：修改代码后引入回归错误
**解决方案**：建立强制性的测试覆盖率阈值，集成 CI/CD
**目标**：核心模块测试覆盖率达到 80%+

### 13. 集成测试复杂
**问题**：各组件间依赖关系复杂，难以进行端到端测试
**解决方案**：使用模拟(mock)技术隔离依赖，创建测试专用配置
**相关测试**：`hevi/tests/p1_skills_integration_test.py`

## 部署运维问题

### 14. 配置漂移
**问题**：生产环境配置与代码仓库不一致
**解决方案**：配置即代码，使用版本控制管理所有配置
**工具推荐**：Ansible, Terraform

### 15. 日志管理困难
**问题**：日志分散，难以排查问题
**解决方案**：统一日志格式，集成 ELK 栈
**日志标准**：`hevi/core/logging.py`

## 数据一致性问题

### 16. 文件完整性验证缺失
**问题**：生成的中间文件损坏但未被发现
**解决方案**：实现 SHA256 校验，确保文件完整性
**相关实现**：`skills/qc-enhancement` 中的 SHA 验证

### 17. 状态管理不一致
**问题**：任务状态在多个组件间不一致
**解决方案**：使用单一事实来源，实现状态同步机制
**相关代码**：`hevi/tasks/` 目录下的状态管理

## 应急处理预案

### 紧急回滚步骤
1. 确认问题影响范围
2. 停止有问题的组件
3. 恢复到上一个稳定版本
4. 验证核心功能
5. 通知相关方

### 监控告警设置
- CPU/内存使用率 > 80%
- 任务失败率 > 5%
- 响应时间 > 30秒
- 关键服务不可达

## 最佳实践总结

1. **防御性编程**：假设一切可能出错的地方都会出错
2. **快速失败**：发现问题立即停止，不要尝试静默恢复
3. **明确错误信息**：错误消息要足够详细，便于定位问题
4. **配置验证**：启动时验证所有关键配置
5. **资源清理**：确保所有申请的资源都被正确释放
6. **监控先行**：在实现功能的同时就考虑如何监控
