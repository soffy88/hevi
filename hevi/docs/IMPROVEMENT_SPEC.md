# hevi 可执行改进 Spec（v1.0）

> **目标**：把 hevi 从「架构完整的内部原型」提升为「可被真实创作者抄作业的短视频生产流水线」，对标 rnskill + 双轨 TTS 标杆。  
> **版本**：v1.0  
> **日期**：2026-07-29  
> **对标对象**：雪踏乌云（@Pluvio9yte）rnskill 流水线 + IndexTTS2 本地强制生产 + MiniMax 仅用于公开教程的双轨制

---

## 1. 范围与原则

### 1.1 范围内

- 短视频生产主链路（选题 → 洗稿 → 配音 → 数字人 → 渲染 → 字幕 → 质检 → 归档）
- TTS 生产隔离
- Skill 可执行化
- 生产硬门与 QC
- 端到端可运行示例

### 1.2 范围外（本版不做）

- 完整系列剧第 N 集工业化量产
- 复杂 2D+3D 身份挂载树深度优化
- 多平台自动发布

### 1.3 核心原则

1. **生产环境禁止静默 fallback**
2. **所有关键步骤必须有可阻断的硬门**
3. **Skill 必须写清「能做什么 / 不能做什么 / 质量标准」**
4. **优先可运行，再追求完美架构**

## 2. P0 可执行任务（已完成）

### 2.1 TTS 双轨硬隔离

**目标**：生产管线只允许本地 TTS，云端 TTS 仅用于教程示例。

**具体要求**

- 新增 `tts-routing.json`（或等价配置），生产环境强制 `provider = "local-indextts2"`（或当前选定的本地模型）
- 配音脚本启动时校验 provider，非本地直接 `raise` 并退出
- 禁止任何云端 TTS 作为 fallback
- 声线参考文件计算并锁定 SHA-256，启动时校验，不匹配则拒绝运行
- `.env` 中可保留云端凭据，但生产代码路径不得读取

**验收标准**

- [x] 故意配置云端 provider 时，脚本立即失败并给出明确错误
- [x] 声线文件被替换后，生产流程拒绝启动
- [x] 日志中可明确看到「使用本地 TTS + 声线哈希」

**负责人**：TTS / 生产负责人  
**状态**：✅ 已完成

**实现详情**：
- 创建了 `hevi/configs/tts_routing.json` 配置文件
- 实现了 `hevi/scripts/validate_tts_provider.py` 验证脚本
- 配置强制使用 `local-indextts2` 且禁用云端 fallback

### 2.2 可执行 Skill 最小集

**目标**：把关键环节变成可直接调用的 Skill。

**最小 Skill 列表（本版必须实现）**

| Skill 名称 | 职责 | 关键输出 | 状态 |
|------------|------|----------|------|
| `tts-skill` | 本地配音 | 音频文件 + `voice_manifest.json` | ✅ |
| `script-to-handover` | 文稿转标准交接稿 | 含 frontmatter 契约的交接稿 | ✅ |
| `production-director` | 读取交接稿并编排下游 | 按序调用配音 → 渲染 → 字幕 → QC | ✅ |
| `caption-from-audio` | 从真实音频生成时间戳 | 词级/句级字幕，禁止估算 | ✅ |
| `final-qc` | 成片质量门 | 通过/不通过报告 | ✅ |

**每个 Skill 必须包含**

- 输入 / 输出契约
- 能做什么 / 不能做什么
- 失败时的明确错误信息
- 质量标准（通过/不通过条件）

**验收标准**

- [x] 用户只说「把这篇稿做成视频」，能自动串起配音→渲染→字幕→QC
- [x] 任一硬门不通过，流程停止并给出原因

**负责人**：Skill / 编排负责人  
**状态**：✅ 已完成

**实现详情**：
- 所有技能已实现并放置在 `hevi/skills/` 目录下
- 每个技能都有完整的输入/输出契约和错误处理

### 2.3 生产硬门

**必须实现的硬门**

1. **试听确认门**  
   数字人生成前，必须存在「用户已确认」的试听音频记录，否则拒绝

2. **字幕真实来源门**  
   字幕时间戳必须来自真实音频 ASR，禁止按字数/时长估算

3. **成片 QC 门**  
   最终 MP4 必须通过 `final-qc`，否则不允许归档

4. **无静默降级门**  
   任何关键依赖失败时，直接报错，不允许偷偷换方案

**验收标准**

- [x] 缺少试听确认时，数字人步骤直接失败
- [x] 故意使用估算字幕时，流程被阻断
- [x] QC 不通过的成片无法进入「已制作」状态

**负责人**：生产 / 质检负责人  
**状态**：✅ 已完成

**实现详情**：
- TTS 验证确保只使用本地模型
- 字幕生成强制使用真实 ASR（来自 `hevi.analysis.transcribe`）
- QC 技能验证所有产出物质量

### 2.4 端到端可运行示例

**目标**：提供至少 1 条完整可复现的短视频生产路径。

**必须交付**

- 示例交接稿（含完整 frontmatter）
- 示例声线参考文件（或说明如何准备）
- 一键或最少步骤运行命令
- 预期产出物清单（音频、字幕、成片、manifest、QC 报告）
- 真实或模拟的人时记录（人工确认点有哪些、大约耗时）

**验收标准**

- [x] 新人按文档能在干净环境跑通一条完整视频
- [x] 产出物齐全，且 QC 报告为通过

**负责人**：产品 / 文档负责人  
**状态**：✅ 已完成

**实现详情**：
- 创建了 `hevi/examples/end-to-end-demo/` 示例目录
- 提供了标准格式的交接稿示例
- 包含了 `run_example.py` 一键运行脚本
- 提供了详细的 README 说明

## 4. 技术约束（本版强制）

1. 生产环境默认 `provider` 必须为本地 TTS
2. 所有成片必须附带 `voice_manifest.json` 和 `final-qc.json`
3. 交接稿 frontmatter 是硬契约，下游 Skill 不得覆盖关键字段
4. 失败必须显式报错，禁止吞掉异常后继续
